# NOXA AI Design Library

Эта папка хранит канонические продуктовые и дизайнерские решения NOXA. Она отделена от инженерной документации, runtime-конфигурации и корневого `README.md`.

## Источник истины

Документы здесь фиксируют подтверждённое продуктовое намерение. Реализация считается доказанной только после проверки кода, production-данных и поведения приложения на реальном устройстве.

## Каноническая структура

1. `01-product-vision.md` — North Star, аудитория и основной цикл продукта.
2. `02-product-constitution.md` — обязательные принципы и запреты.
3. `03-home-map-mvp-spec.md` — финальная спецификация Home/Map для MVP.
4. `04-mvp-v2-boundary.md` — жёсткая граница первого релиза и будущих функций.
5. `05-social-trust-v2.md` — утверждённая архитектура доверия, сохранённая для V2.
6. `06-decision-log.md` — краткий журнал окончательных решений.

## Рабочий процесс

Для каждой задачи:

1. Проверить актуальный `main`, production Supabase и runtime evidence.
2. Сформулировать одну проблему и ожидаемый пользовательский результат.
3. Принять решение без бесконечного углубления в редкие edge cases.
4. Отделить MVP от V2.
5. Подготовить UI/UX-spec и критерии приёмки.
6. Реализовать в отдельной ветке и PR.
7. Проверить на Android-устройстве или эмуляторе.
8. Только после проверки обновить статус документа.

## Stop rule

Если основной сценарий уже понятен и безопасен, обсуждение прекращается. Редкие сценарии фиксируются как ограничения или V2, но не блокируют MVP.

> Сначала пять функций на 10/10. Потом расширение продукта.
