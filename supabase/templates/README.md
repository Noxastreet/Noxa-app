# NOXA Auth email setup

These hosted Auth settings are not database migrations. Keep this file in sync with the
Supabase project and never commit SMTP passwords.

## URL configuration

In **Authentication → URL Configuration**:

- Site URL: `noxa://auth/callback`
- Production/development-build redirect: `noxa://auth/callback`
- Password-recovery redirect: `noxa://reset-password`
- Expo Go development-only redirect: `exp://**/--/auth/callback`
- Expo Go password-recovery redirect: `exp://**/--/reset-password`

Use exact production paths where possible. Remove the broad Expo Go redirect before release.

## Custom SMTP

The NOXA project was created after Supabase restricted template customization for new Free
projects using the default SMTP provider. Configure custom SMTP before applying the template.

For temporary Gmail-based alpha testing:

- Sender name: `NOXA`
- Sender email: the Gmail account used for NOXA
- Host: `smtp.gmail.com`
- Port: `587`
- Username: the full Gmail address
- Password: a Google App Password, never the normal Google password

Store the App Password only in the Supabase Dashboard. For production, use a dedicated
transactional provider and a NOXA-owned sending domain with SPF, DKIM, and DMARC.

## Confirm signup template

In **Authentication → Email Templates → Confirm signup**:

- Subject: `Confirm your NOXA account`
- Body: copy `supabase/templates/confirmation.html`

The template must keep `{{ .ConfirmationURL }}` so Supabase verifies the token before returning
the user to the `emailRedirectTo` URL generated by the app.
